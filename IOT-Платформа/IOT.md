# Расчет нагрузки IoT-платформы

## 1. Входные параметры (Допущения)

| Параметр | Значение | Примечание |
| :--- | :--- | :--- |
| **Количество устройств** | 1 000 шт. | 500 датчиков температуры + 500 датчиков пыли |
| **Частота опроса** | 1 сообщение / 10 сек | Стандарт для промышленного мониторинга |
| **Размер пакета (JSON)** | 250 байт | ID, timestamp, значение, статус |
| **Коэффициент пиковой нагрузки** | 2.5x | Учет аварийных всплесков и пиковых часов |
| **Глубина Hot Storage** | 30 дней | Оперативная база данных |
| **Глубина Cold Storage** | 1 год | Архив |

## 2. Расчет нагрузки по узлам схемы

| Блок схемы | Метрика | Средняя нагрузка | Пиковая нагрузка | Комментарий |
| :--- | :--- | :--- | :--- | :--- |
| **1. Сбор данных** | Транзакции (TPS) | 100 msg/sec | 250 msg/sec | Входящий поток от датчиков |
| | Трафик (Bandwidth) | 0.2 Мбит/с | 0.5 Мбит/с | Очень низкий трафик |
| **2. Обработка и фильтрация** | Нагрузка на CPU | Низкая (<5%) | Средняя (15-20%) | Зависит от сложности алгоритмов очистки |
| | Запись в БД (Write IOPS) | 100 записей/сек | 250 записей/сек | Рекомендуется батчинг (пакетная запись) |
| **База данных телеметрии** | Объем данных / сутки | ~2.16 ГБ | — | Сырые данные |
| | Объем данных / 30 дней | ~65 ГБ | ~130 ГБ | С учетом индексов СУБД (x2) |
| **3. Мониторинг и анализ** | Генерация алертов | ~1 алерт/сек | ~3 алерта/сек | При условии, что 1% данных вызывает алерты |
| **4. Формирование отчетов** | Запросы пользователей | ~100 запросов/день | — | Низкая частота, но тяжелые запросы |
| | Архивация (Batch) | 2 ГБ / ночь | — | Кратковременная высокая нагрузка на Disk I/O |

## 3. Вывод по нагрузке

| Показатель | Оценка |
| :--- | :--- |
| **Общая нагрузка системы** | **Низкая / Средняя** |
| **Основное узкое место** | Дисковая подсистема БД (Write IOPS) |
| **Критический фактор** | Надежность записи и правильная настройка индексов |
| **Потенциал масштабирования** | До 10 000+ датчиков без смены архитектуры (при горизонтальном масштабировании) |
